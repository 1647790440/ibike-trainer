# 心率带能做什么：功能清单与决策表

> **进度（2026-09）**：**F1~F4 已实现**（连接、心率入库、心率区间、上限保护）。
> 代码在 `ibike/heartrate.py`，测试在 `tests/test_heartrate.py`，用法见 README 的
> 「心率带」一节。下面 F5 及之后的仍是候选，等骑几次攒够数据再决定。

> 配套文档：[`apple-watch-heart-rate.md`](apple-watch-heart-rate.md)（苹果手表那条路的调研）。
> 结论先说：**心率带比苹果手表那条路强，而且强的不止一点。**

---

## 0. 为什么心率带这条路明显更好

| | Apple Watch（上一份调研） | 心率带（标准 BLE） |
|---|---|---|
| 链路 | 手表 → iPhone 广播 → 电脑 | **直连电脑** |
| 需要 iPhone 在场 | 要 | 不要 |
| 需要手表开 workout | 要（会占用手表自己的训练记录） | 不要 |
| 首次连接 | 广播 App 必须前台可见 | 不用配对，扫描即可 |
| 传感器 | 光学（滞后 + 运动时易受干扰） | **心电**（快、准） |
| 30/15 这类短间歇 | 心率根本追不上，数据基本没用 | 能跟上 |
| 除了心率还能拿到什么 | 只有 BPM | **还有 RR 间期**，Polar H10 甚至能给 130Hz 原始心电 |

**最关键的一条**：`0x2A37`（心率测量特征值）里除了当前心率，还带 **RR 间期**（逐拍间隔）。
有 RR 间期就能算 **HRV（心率变异性）** —— 也就是说，我上次归类为"必须靠 HealthKit
事后同步"的「晨起就绪度」这类功能，**用心率带自己就能做一部分**，不需要手机参与。

需要说清楚的边界：

- RR 间期算 HRV 只在**静息或很低强度**下可靠。骑到 150bpm 时呼吸和运动伪影会把 RR
  搅乱，"运动中 HRV"看着很酷但没有可解释性，我不建议做。
- Polar H10 的 PMD 服务（`fb005c80-…`，ECG 特征值 `fb005c82-…`，130Hz）能取原始心电。
  这个更多是"能存下来看看"，对训练决策没有直接价值。
- 睡眠、VO2max、活动环这些**仍然拿不到**（那些只有 HealthKit 有）。

## 1. 现在程序里有什么、缺什么（已核对代码）

| 能力 | 现状 |
|---|---|
| 解析骑行台上报的心率 | **有**（`ftms.py` 的 `heart_rate_bpm`） |
| 界面显示实时心率 | **有**（`app.js` 的 `mHr`，就是那个 "心率 -- bpm" 格子） |
| 标准心率服务 `0x180D` 客户端 | **完全没有** —— 这是所有后续功能的前提 |
| 心率进每秒轨迹 | **没有** |
| 报告里有任何心率字段 | **没有**（平均/最大/曲线/区间都没有）|
| 心率区间 | **没有**（功率区间现成，`workouts.zone_of` 可以照着做一套）|

也就是说：现在那个"心率"格子只在骑行台自己上报心率时才有数，而它不上报。
**心率带接不进程序，就算接进去也留不下数据。**

## 2. 功能清单

标注：**工作量**是相对量级；**依赖**指"必须先有什么"。

### 第一层：基础设施（✅ 已实现）

| 编号 | 功能 | 做什么 | 依赖 | 工作量 |
|---|---|---|---|---|
| **F1** ✅ | **心率带连接** | 新增一个独立的心率设备客户端：扫描（按 `0x180D` 过滤）、连接、订阅、断线自动重连；记住上次那根带子的地址；界面显示连接状态 | — | 中 |
| **F2** ✅ | **心率入库** | 心率每秒进 trace；报告里给出平均/最大心率 + 心率曲线（和功率画在同一张图，双 Y 轴） | F1 | 小 |
| **F3** ✅ | **心率区间分布** | 按 5 区统计停留时间，和现有的功率区间分布并排显示 | F1、F2、需要"最大心率"（+可选静息心率） | 小 |
| **F4** ✅ | **心率上限保护** | 心率超过设定上限并持续 N 秒 → 自动把目标功率降 5%，回落后恢复。**这是安全保护，不是控制方式** | F1 | 小 |

> 关于 F4 的边界：FTMS 里有 `Set Target Heart Rate (0x06)`，但**不要用它做闭环控制**。
> 心率滞后 30~60 秒、受咖啡因/情绪/温度影响，闭环控出来的功率会非常难看。
> 心率只适合当"刹车"，不适合当"油门"。

### 第二层：功率 + 心率一起看（这才是"完善训练"的地方）

| 编号 | 功能 | 做什么 | 依赖 | 工作量 |
|---|---|---|---|---|
| **F5** | **解耦率 Pa:HR** | 把一次训练切成前后两半，比较"功率/心率"比值的变化百分比。有氧耐力最经典的指标，长距离课表尤其有用 | F2 | 小 |
| **F6** | **心率漂移** | 同样功率下心率随时间爬升多少（通常看后半程 vs 前半程）。用来看"这个强度我到底撑不撑得住" | F2 | 小 |
| **F7** | **效率因子 EF 趋势** | `EF = NP / 平均心率`，存进报告并画跨训练的曲线。同一个功率心率越来越低 = 有氧能力在涨 | F2、需要历史报告（已有） | 小 |
| **F8** | **心率区间 vs 功率区间背离提示** | 设的是 Z2 功率、心率却一直在 Z4 → 提示"可能是 FTP 设高了，或者今天状态不好"。对"乳酸科学训练"那套价值最大 | F2、F3 | 小 |
| **F9** | **间歇恢复判读** | 每组结束时心率、组间恢复 60 秒掉多少 bpm（HRR）。加进现有分段统计当两列 | F2 | 小 |
| **F10** | **卡路里双源估算** | 现在只有"按 23% 做功效率折算"一个粗值。有持续心率后可以用 Keytel 公式算一个更贴近实际的消耗，两个数并排显示 | F2、需要体重/年龄/性别 | 小 |

### 第三层：用 RR 间期（附加，取决于买的是哪根带子）

| 编号 | 功能 | 做什么 | 依赖 | 工作量 |
|---|---|---|---|---|
| **F11** | **静息 HRV 记录** | 训练前静坐/静躺 2 分钟采 RR，算 RMSSD，存成一条时间序列 | F1、带子支持 RR 间期 | 中 |
| **F12** | **晨起就绪度提示** | 用 HRV 基线 + 静息心率基线，在开始训练前给一句"今天适合上强度还是轻松骑" | F11（攒够 7~14 天才准） | 中 |
| **F13** | **原始 ECG 存盘**（仅 Polar H10） | 130Hz 心电存成文件、画出来看 | F1、H10 专属协议 | 中 |

## 3. 需要新增的设置项

| 参数 | 用途 | 怎么来 |
|---|---|---|
| 心率带地址 | 下次自动重连 | 连过一次就记住 |
| 最大心率 | 心率区间（%HRmax 法） | `220-年龄` 估算，或实测 |
| 静息心率 | 心率区间（储备心率法 / Karvonen，更准） | 手动填，或用 F11 自动取基线 |
| 体重、年龄、性别 | F10 卡路里公式 | 手动填 |
| 心率上限 | F4 保护 | 手动填，默认不启用 |
| 心率区间算法 | %HRmax 还是储备心率 | 设置里选 |

## 4. 几个必须提前知道的坑

1. **短间歇不要逐秒看心率。** 30/15 这种，心率在第一组就追不上目标，逐秒看只会得到
   一条"永远滞后"的曲线。要看就按"每组平均 / 组末值 / 恢复降幅"看（F9 就是这么设计的）。
2. **胸带要湿润电极才有好读数。** 冬天刚戴上头一两分钟可能乱跳，第一层做完之后
   界面要能显示"心率数据可疑"（比如长时间不变或超出物理范围）而不是照单全收。
3. **两根 BLE 设备同时连**（骑行台 + 心率带）在 macOS 上没问题，但要实测断线重连：
   心率带飘出范围、或骑行台先连后连，都不能连带把另一条搞断。
4. **`0x180D` 是不用配对的**，所以不会和"骑行台已经占着连接"冲突 —— 它们是两个独立外设。
5. **HRV 需要耐心**：单次 HRV 数字没有意义，要连续记录一两周才有基线可比。

## 5. 我的建议

**第一步只做 F1 + F2 + F3**，一次做完。理由：

- 它们互相咬合（没有连接就没有数据，没有数据就没有区间），拆开做等于白做两遍界面
- 做完之后您手上有"心率 + 功率"的完整历史数据，**第二层那几个指标全是趋势型的**，
  骑三到四次之后才有得看，现在选哪个都是拍脑袋
- 顺便验证第 4 节里的两个坑（双设备稳定性、心率数据可信度）

**第二步**（骑过几次之后）再做 F5~F10 里您觉得有用的 —— 从价值看，
**F5（解耦率）、F6（心率漂移）、F7（EF 趋势）**这三项是核心，
F8/F9/F10 是锦上添花。

**F11/F12（HRV）**建议最后再说：它需要额外的手动流程（每次训练前静坐 2 分钟），
如果嫌麻烦就不会坚持，而断断续续的 HRV 数据没有价值。

**F13** 基本是玩具，除非您对心电波形本身感兴趣。
