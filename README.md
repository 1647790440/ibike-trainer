# iBike · 本地智能骑行控制台

用浏览器给智能骑行台设定一个目标功率，程序通过蓝牙直接控制骑行台把功率稳住（ERG 模式）。
跑在你自己电脑上，**不联网、不要账号、不花钱，训练数据全在本机**。

适用于「只想认真踩完今天的课表」这件事：设定 60 分钟 / 130 瓦，然后专心踩，
剩下的交给程序。想练别的就换一种模式，或者自己排课表。

## 能做什么

| | 说明 |
|---|---|
| **恒定功率** | 设定时长和瓦数（例如 60 分钟 / 130W），骑行台自动调整阻力让你始终踩在这个功率附近 |
| **间歇训练** | 6 个内置方案（4×4、2×20、30/15、5×5、Over-Under、Tabata），强度按你的 FTP 百分比定义 |
| **自定义课程** | 自己排小节（时长 + 功率），存成固定课程反复用，最多 80 节 |
| **FTP 测试** | 坡道 / 20 分钟 / 8 分钟三种方案，测完自动算出阈值功率并存下来，后面的课表跟着缩放 |
| **心率带** | 标准蓝牙心率带直连：实时心率与心率区间、报告里的心率统计与曲线、可选的心率上限保护 |
| **训练报告** | 每次训练结束自动保存，可回看、可删除；另有示例报告可以在没骑车时预览界面 |
| **手机操作** | 电脑和手机连同一个 Wi-Fi，手机浏览器打开就行（启动时终端会打印二维码） |

## 需要什么

| | 要求 |
|---|---|
| 电脑 | macOS / Linux / Windows（Windows 见下方说明）。需要 **Python 3.9 或更高** |
| 骑行台 | 支持标准蓝牙 **FTMS** 协议，并且至少能设「目标功率」或「目标阻力」其中之一 |
| 心率带 | 可选。任何支持标准蓝牙心率服务（`0x180D`）的都可以：迈金、Polar H10、Wahoo TICKR、Coospo…… |
| 网络 | **不需要外网**。只有手机操作时才需要局域网 |

不支持 ANT+，也没有为任何厂商的私有协议做适配。如果你不确定自己的设备行不行，
先跑 `./run.sh --scan`（见下方「排查问题」），它会列出扫到的设备并标明是不是 FTMS。

## 快速开始

### 1. 下载并启动

```bash
git clone https://github.com/1647790440/ibike-trainer.git
cd ibike-trainer
./run.sh
```

`run.sh` 第一次运行会自动创建虚拟环境并装依赖（`bleak` / `aiohttp` / `qrcode`，
总共几 MB），然后启动服务并打开浏览器。

> **macOS 首次运行**必须在弹窗里允许蓝牙权限（在
> **系统设置 → 隐私与安全性 → 蓝牙** 里勾选你的终端 App，比如「终端」或「iTerm」），
> 否则搜不到任何设备。
>
> **Windows**：`run.sh` 是 bash 脚本，用 Git Bash 或 WSL 跑；也可以手动
> `python -m venv .venv` 装好依赖后跑 `python main.py`。Windows 路径没有实测过，
> 遇到问题欢迎开 issue。

### 2. 连接设备（「1 连接设备」页）

骑行台通电、踩两圈唤醒它；心率带戴上（电极沾点水）。
点一次「扫描蓝牙设备」，下面会同时列出骑行台和心率带，**各点一下就连上**。

两台设备可以只连一台——不连心率带也能正常训练；顺序随意。
连过的设备都会记住地址：**心率带**下次启动自动连回来；**骑行台**在训练中途掉线时
（比如休息久了它自己关机）程序会在后台自己连回来，不用你跑到这个页面手动点。

连上之后，两块状态卡片里会立刻出现实时数字（功率/踏频/速度/阻力、心率/区间/电极），
一眼就能确认到底连上没有。

### 3. 设定目标并开始（「2 训练」页）

选一种模式、填参数、点「开始训练」。开始后会自动切到训练页，实时显示功率、踏频、
心率（和心率区间）、剩余时间、平均/最大功率、标准化功率、距离、做功。
训练中随时可以 ±5/±10 W 微调目标、暂停、跳过本段或结束。

**停下来会自动暂停**：功率和踏频都归零超过 15 秒，秒表就停住（接电话、喝水、
站起来缓一缓都算），重新踩起来会自动继续，不用去够鼠标。停下来的那一段一秒都
不会算进骑行时长和平均功率——所以那 15 秒的确认期也从停止的那一刻就不计了。
手动按下的暂停、骑行台掉线挂起都不会自动继续，必须你自己点「继续」。

### 4. 看总结

点「结束」或跑满时长后会生成总结，**并且自动存进「训练报告」**。
可以「再来一次」用同样的参数重开，或「关闭」回到设定页。

## 界面

界面分成两页，顶部导航切换，停留的页面会被记住：

| 页面 | 内容 |
|---|---|
| **1 连接设备** | 扫描与连接、骑行台状态与实时数据、心率带状态与实时数据 |
| **2 训练** | 训练目标、心率参数、实时数据、训练总结、训练报告 |

## 四种训练模式

在「2 训练」页顶部切换：

- **恒定功率** —— 最常用。设时长和瓦数就开始。
- **间歇训练** —— 选内置方案，按需改参数（组数、强度、时长…），下方实时生成课表预览。
- **自定义课程** —— 自己排小节，点「开始训练」会先自动保存再开始。
- **FTP 测试** —— 第一次用建议先测一次；测出来的值会用在所有间歇和自定义课程里。

每种模式背后都有一些值得知道的细节（为什么测试必须用不同控制方式、为什么达标率只算
高强度段、区间怎么划分），写在 **[docs/training-methods.md](docs/training-methods.md)**。

## 心率带

可选，但装上之后报告里会多出一整块心率分析。

| | 说明 |
|---|---|
| 实时 | 界面显示心率、当前心率区间、电极接触状态和带子电量 |
| 报告 | 平均/最大心率、5 个区间的停留时间、与功率同图的心率曲线（双刻度） |
| 心率上限保护 | 可选。心率超过设定值并持续 10 秒就自动把目标下调 5%，最多降到本段的 80%；心率回落后再回到原计划 |

**区间怎么算**：设置里可以选「按最大心率百分比」，或者「按储备心率（Karvonen）」——
后者需要静息心率，把"你躺着时的心率"当作真正的零点，同样跑 150bpm，静息 50 的人
比静息 70 的人轻松得多，所以算得更准。

**心率上限保护是一道刹车，不是控制方式。** 心率本身滞后 30~60 秒，拿它做闭环一定会
振荡，所以程序不会去"追"心率，而是分几步往下让。自由骑行模式下程序本来就不控制功率，
这时只提示、不改功率。

**连上之后会告诉你这根带子支不支持 RR 间期**（决定以后能不能做静息 HRV）。
心率相关的后续候选功能见 **[docs/heart-rate-features.md](docs/heart-rate-features.md)**。

## 训练报告

每次训练结束自动保存一份，在「2 训练」页下方的「训练报告」列表里，按时间倒序。
点开就能看到和刚骑完时一模一样的完整总结；点条目右侧的 `×` 删除，右上角清空全部。

报告存在 `data/reports/` 下，**一次训练一个文件**，纯文本 JSON，可以直接备份或转格式。
文件里除了功率/心率/踏频/阻力曲线和统计，还带两样诊断用的东西：

- **这场训练的事件表**——什么时候开始、暂停了几次、骑行台有没有掉线重连、控功率
  方式有没有切换过。想搞清楚"中间那两段空白是怎么回事"时，看它就够了。
- **休息段的心率**——暂停/挂起期间心率是单独记的，不并入训练统计（休息时的心率
  不是训练负荷）。报告里会给出每一段的时长、心率从多少掉到多少、以及**停下来
  60 秒内心率回落了多少**：同样强度下掉得越快，说明有氧恢复能力越好，适合自己
  跟自己比。

**想先看看报告长什么样**（没空真骑的时候）：

```bash
.venv/bin/python tools/make_sample_reports.py           # 生成 8 份示例报告
.venv/bin/python tools/make_sample_reports.py --clear   # 删掉示例数据
```

这些是模拟生成的，但**格式和真实训练完全一致**，界面上看到的就是真东西。
每份都带「示例」角标，`--clear` 也只删示例、不动你的真实记录。

## 数据与备份

| | |
|---|---|
| 位置 | 默认在项目下的 `data/`：`reports/`（训练报告）、`custom_workouts.json`（自定义课程）、`settings.json`（FTP、心率参数） |
| 换位置 | 设环境变量 `IBIKE_DATA_DIR=/path/to/your/data` 再启动 |
| 备份 | 直接复制 `data/` 整个目录即可（都是纯文本） |
| 卸载 | 删掉项目目录和 `data/` 就干净了，程序不在系统里留任何东西 |

报告上限 500 份（每份含曲线约 30KB）。超出后删最旧的，并在日志里明确记一条。

## 命令行参数

`run.sh` 会把参数透传给 `main.py`：

| 命令 | 作用 |
|---|---|
| `./run.sh` | 正常启动 |
| `./run.sh --sim` | **用模拟设备**（骑行台 + 心率带都是模拟的），不接硬件也能把完整流程走一遍 |
| `./run.sh --sim-dumb` | 模拟一台「收下目标功率但不执行」的骑行台，用来看自动降级的完整过程 |
| `./run.sh --scan` | 只扫描设备然后退出，同时列出骑行台和心率带 |
| `./run.sh --diag` | 诊断「为什么功率压不到设定值」（约 4 分钟，全程保持踩踏） |
| `./run.sh --port 9000` | 换端口（默认 8765） |
| `./run.sh --host 127.0.0.1` | 只监听本机（默认 `0.0.0.0`，手机也能访问） |
| `./run.sh --no-browser` | 不自动打开浏览器 |

## 排查问题

### 先扫一遍

```bash
./run.sh --scan                       # 列出扫到的骑行台和心率带
.venv/bin/python scan.py --pick       # 连接并打印这台设备完整的 GATT 结构
```

`scan.py` 会直接告诉你设备支不支持标准 FTMS、能不能接受目标功率。
如果输出显示「没有发现标准 FTMS 服务」，说明它走的是私有协议——把完整输出贴到
issue 里，才有可能加上适配。

### 常见问题

**扫描不到骑行台**
- 确认它已通电，并且被踩动唤醒（很多骑行台静止几分钟就休眠）
- 关掉手机上正在占用它的 App（Zwift / MyWhoosh / 厂商 App 会独占蓝牙连接）
- 蓝牙同时只能被一台设备连接。骑行台已经被手机连着时，电脑就连不上
- macOS 首次运行要在「系统设置 → 隐私与安全性 → 蓝牙」里给终端授权
- 换 `./run.sh --scan-timeout 15` 扫久一点

**连上了，但「开始训练」按钮是灰的**
- 按钮只要求连上骑行台（心率带不用连）。检查「2 训练」页顶部的状态胶囊

**骑到一半数据断了**
- 界面会提示「已经有一阵子没收到骑行台数据了」。程序会停止累计做功和距离、
  也停止调整阻力，直到数据恢复——不会拿最后一刻的功率值继续算
- 常见原因是骑行台休眠、蓝牙被手机抢走、距离太远。靠近一点通常会自动恢复

**停下来接电话/喝水，需要按暂停吗？**
- 不需要，停踩超过 15 秒程序会自动帮你停表（秒表、平均功率、区间分布都跟着停），
  重新踩起来自动继续。想手动停也可以，按「暂停」的效果一样
- 差别只有一点：手动暂停会顺便让骑行台松开阻力，自动暂停不动骑行台（不然有些
  固件会连数据一起停掉，程序就再也检测不到你回来了）

**休息的时候骑行台自动关机了，训练会不会没了？**
- 不会。掉线只是把训练**挂起**：秒表停住（休息时间不算进骑行时长），已经骑过的
  数据、曲线、心率全都留着，界面会提示「骑行台掉线了，正在后台自动重连」
- **还会自己连回来**：程序每 4-20 秒试一次（先按记住的地址直连，连不上再**扫一遍
  广播**兜底）。台子是被踩醒的，所以它会一直试到你重新骑起来为止。接上的那一刻
  程序会让台子重新跑起来（只 Start、不下发目标），然后只要检测到你在踩（踏频或
  功率任一达标），就自动继续这一场训练——全程不用去设备页，也不用点「继续」
- 真机实测：停下来不踩之后，台子约 47 秒报「Stopped」、约 109 秒自动关机。所以
  休息超过两分钟基本一定会走这条自动重连的路（也正因如此才值得做成自动的）
- 喝水、站起来缓一缓这种短休息不会碰断蓝牙，台子一直连着，跟平时一样按「暂停」
  就行；只有台子自己关机休眠/走远/被手机抢走才会断链，那也只会挂起，不会结束
- 如果自动重连没成功（或者你手动去连），回到「1 连接设备」连上骑行台，程序会把这个
  台子**接回这一场训练**（不是重新开一场），再回「2 训练」点「继续」接着骑
- 只有三种情况才会真的结束这一场：点「结束」、跑满时长、点「断开」。
  「断开」会先把这场收尾存成报告，所以点它时会再确认一次

**连上了但功率控不住**
- 看界面底部那行提示。显示「骑行台不能把功率压到设定值……已自动切换到闭环阻力控制」
  说明降级已经发生，稍等一会儿功率会收敛
- 闭环模式下必须保持踩踏。踏频低于 25rpm 时不调整阻力（有意设计）
- 两种方式都不行就跑 `./run.sh --diag`，它会告诉你固件到底是哪种毛病

**手机关掉页面、电脑接着骑**
- 训练跑在电脑上，关掉页面不影响；重新打开会自动接上当前状态

**手机打不开页面**
- 手机和电脑要在同一个 Wi-Fi 下（别一个连 5G、一个连访客网络）
- 用启动时终端打印的那个 `192.168.x.x` 地址，不要用 `127.0.0.1`
- macOS 防火墙可能拦了 8765 端口，在「系统设置 → 网络 → 防火墙」里放行

**训练到一半不小心关了服务 / 点了断开**
- 这一场会照常存成报告（结束原因写「断开连接」），不想要直接删掉
- 只是想换个台子继续骑的话，**不要点「断开」**：直接扫描并连上新的骑行台，
  训练会接过去接着骑
