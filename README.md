# iBike · 本地智能骑行控制台

用浏览器控制智能骑行台：设一个目标功率，程序通过蓝牙让骑行台把功率稳住。
全部跑在你自己电脑上，不联网、不要账号，训练数据留在本机。

## 功能

| 功能 | 说明 |
|---|---|
| 恒定功率 | 设时长和瓦数（比如 60 分钟 / 130W），骑行台自动调阻力把功率稳住 |
| 间歇训练 | 6 个内置方案（4×4、2×20、30/15、5×5、Over-Under、Tabata），强度按 FTP 百分比 |
| 自定义课程 | 自己排小节（时长 + 功率），存下来反复用，最多 80 节 |
| FTP 测试 | 坡道 / 20 分钟 / 8 分钟三种方案，测完自动算出阈值功率 |
| 心率带 | 标准蓝牙心率带直连：实时心率与区间、报告心率统计、可选的心率上限保护 |
| 训练报告 | 每次训练自动保存；按月日历看哪天骑了；曲线可以鼠标悬停读数 |
| 悬浮窗 | 功率/心率/剩余时间浮在屏幕角落，置顶、点击穿透，看视频不挡画面 |
| 手机操作 | 电脑手机连同一个 Wi-Fi，手机浏览器打开就能用（终端会打印二维码） |

## 需要什么

- **电脑**：macOS / Linux / Windows，Python 3.9 以上
- **骑行台**：支持蓝牙 FTMS 协议，能设「目标功率」或「目标阻力」
- **心率带**（可选）：支持标准蓝牙心率服务 `0x180D` 的任意品牌
- **网络**：不需要外网；手机操作时才用到局域网

不支持 ANT+，也没有适配任何厂商私有协议。不确定设备行不行就先跑 `./run.sh --scan`。

## 安装与启动

```bash
git clone https://github.com/1647790440/ibike-trainer.git
cd ibike-trainer
./run.sh
```

`run.sh` 第一次会建虚拟环境并装依赖，然后启动服务、打开浏览器。
之后直接 `./run.sh` 即可。

没有骑行台想先看看界面：`./run.sh --sim`。

macOS 首次运行要在弹窗里允许蓝牙权限（**系统设置 → 隐私与安全性 → 蓝牙** 里勾选你的终端）。
Windows 上用 Git Bash 或 WSL 跑 `run.sh`，也可以手动建虚拟环境后 `python main.py`。

## 用起来

**一、连接设备**（「连接设备」页）
骑行台通电、踩两圈唤醒；心率带戴上。点「扫描蓝牙设备」，列表里点一下就连上。
只连骑行台也能训练。设备地址会被记住：心率带下次启动自动连回，骑行台在训练中掉线
会被后台自动重连。

**二、设定目标**（「训练」页）
上面是骑手信息（最大心率、FTP、心率上限保护），下面是训练目标：选模式、填参数、
点「开始训练」。

**三、骑**
开始后自动切到实时面板：功率、踏频、心率、剩余时间、平均/最大功率、标准化功率、
距离、做功。训练中可以 ±5 / ±10W 微调、暂停、跳过本段、结束。
功率和踏频同时归零超过 15 秒会自动暂停，重新踩起来自动继续（这段时间不计入时长和平均值）。

**四、看报告**（「报告」页）
训练结束自动生成报告并落到这一页。上面是按月的训练日历，下面是报告列表。
打开一份报告，鼠标在功率/心率曲线上移动会显示那一刻的功率、目标、心率。

## 页面

| 页面 | 内容 |
|---|---|
| 连接设备 | 扫描与连接、骑行台实时数据、心率带实时数据、运行日志 |
| 训练 | 骑手信息、训练目标、骑行中的实时面板、训练总结 |
| 报告 | 训练日历、报告列表、单次报告详情 |

## 训练模式

- **自定义课程** —— 自己排小节，点「开始训练」会先自动保存
- **恒定功率** —— 设时长和瓦数，最常用
- **间歇训练** —— 选内置方案、改参数，下方实时预览课表
- **FTP 测试** —— 建议先测一次，结果会用在所有间歇和自定义课程里

细节见 [docs/training-methods.md](docs/training-methods.md)。

## 悬浮窗

在「连接设备」页点「悬浮显示」，屏幕右上角出现一个透明小窗：功率、剩余时间、
心率区间、踏频、目标功率和当前状态。点击穿透，不影响底下的操作；再点一次关闭。

想换位置/透明度/字号：

```bash
./run-overlay.sh --anchor top-left --pos 24,60 --alpha 0.8 --size 1.3
```

详见 [docs/overlay.md](docs/overlay.md)。

## 数据

| 文件 | 内容 |
|---|---|
| `data/settings.json` | FTP、最大心率、心率上限、上次连接的设备地址 |
| `data/reports/*.json` | 每次训练的完整报告（含轨迹、分段、心率） |

报告是历史快照，不会被改写。备份就是拷贝整个 `data/` 目录。
想换位置可以用环境变量指定，例如 `IBIKE_DATA_DIR=~/my-ibike ./run.sh`。

## 命令行参数

```
--scan              只扫描设备然后退出（排查用）
--sim               用模拟骑行台，不需要硬件
--port 8765         监听端口
--host 0.0.0.0      监听地址（默认允许手机访问）
--no-browser        不自动打开浏览器
--diag              设备诊断（连上后读一遍能力与特征值）
```

## 出问题

| 现象 | 处理 |
|---|---|
| 扫不到设备 | 确认骑行台通电、没被手机 App 占用；macOS 检查蓝牙权限；`./run.sh --scan` 看得到吗 |
| 连上但功率不动 | 用 `./run.sh --diag` 看这台设备支不支持 FTMS 控制点 |
| 功率总是偏高/偏低 | 报告里的「相对目标功率的分布」能看出是波动大还是系统性偏差 |
| 手机打不开 | 确认同一个 Wi-Fi、电脑防火墙放行端口；终端里打印的二维码扫一下更快 |
| 端口被占用 | 换端口 `./run.sh --port 8766` |

## 开发

```bash
.venv/bin/python tests/test_session_lifecycle.py   # 单个后端测试
.venv/bin/python selftest.py                       # 全部后端测试
node tests/test_frontend_smoke.js                  # 前端冒烟
```

代码结构：

```
main.py            启动入口（参数、模拟器、二维码）
ibike/session.py   训练会话：课表推进、统计、暂停、心率
ibike/server.py    HTTP + WebSocket 接口
ibike/trainer.py   骑行台蓝牙客户端（FTMS）
ibike/heartrate.py 心率带客户端与心率区间
ibike/reports.py   报告存取
ibike/web/         前端（原生 HTML/CSS/JS，无需构建）
overlay.py         悬浮窗（macOS 原生窗口）
```

设计取舍和协议细节在 `docs/`：`design-notes.md`（为什么这样实现）、
`heart-rate-features.md`（心率功能）、`overlay.md`（悬浮窗）、
`packaging-options.md`（打包可行性）。
